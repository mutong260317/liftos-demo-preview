# LiftOS V0.3 — Gym Experience

Baseline: `main@509fdaf5022a4a5e3e5cf5490a2e1ec487100ab6`

## Goal

Turn V0.2.1 from a safe functional prototype into a faster real-gym logger.

Primary principle: **Do not interrupt training.**

Secondary principle: **Every displayed value must distinguish previous performance, suggestion, and actual recorded data.**

No AI/API, no social, no cloud sync, no login in this version.

## P0 — must ship

### 0. Repository hygiene

- Fix current `README.md` Chinese mojibake/encoding corruption.
- Keep UTF-8 text intact in future edits.
- Do not change business behavior while fixing README.

### 1. Previous workout values

For each set during an active workout, show prior performance without writing it into the current set.

Support preference:
- `same_routine` (default)
- `any_workout`

Display examples:
- `上次 22kg × 10`
- first-time exercise: blank / `—`

Requirements:
- previous values are read-only context
- never auto-mark reps/RIR as actual data
- set N maps to previous set N when available
- extra sets beyond previous workout show blank previous value

### 2. One-tap repeat / copy previous set

During an active exercise:
- one-tap action to copy the immediately previous completed set's weight + reps + RIR into the current set
- separate action to copy corresponding prior-workout set into current editable fields
- copied values remain editable and are not completed until user explicitly completes the set

Goal: common repeated working sets should take one action before completion.

### 3. Dynamic add/delete/reorder sets

Allow within an active exercise:
- add set
- delete uncompleted set
- delete completed set only after confirmation, with PR/volume recalculation
- reorder sets if practical without harming mobile usability

Persistence must survive reload.

### 4. Complete set-type model

Keep unified set shape, extend UI support for:
- warmup
- work
- drop
- failure
- amrap

Rules:
- set type can be changed before completion
- changing completed set type requires recalculation
- `failure` and `amrap` are not synonyms: AMRAP = max reps target; failure = actual endpoint flag/type
- stats must clearly define which set types count toward work-set volume/PR

Default stats policy for V0.3:
- warmup excluded from work-set count and PR by default
- work/drop/amrap/failure included in session volume if valid load/reps exist
- warmup inclusion can be a preference later; do not overbuild now

### 5. Assisted bodyweight model

Current `weight=0` bodyweight model is insufficient for assisted pull-ups/dips.

Add explicit load mode, e.g.:
- `bodyweight`
- `added_weight`
- `assisted`
- `external`

For assisted movements store assistance separately, e.g.:
- bodyWeightKg
- assistanceKg
- addedWeightKg

Do **not** encode 40kg assistance as negative weight.

Display examples:
- `自重 × 8`
- `自重 + 10kg × 6`
- `辅助 40kg × 10`

PR policy:
- bodyweight reps PR supported
- added-weight reps/load PR supported
- assisted PR should prefer **less assistance at equal/better reps**
- e1RM remains disabled for pure/assisted bodyweight unless a future model explicitly supports it

### 6. Duration exercises

Support exercises whose primary metric is time, e.g. plank.

Set must support either:
- reps-based
- duration-based

Duration UI:
- inline stopwatch
- manual seconds entry
- completion persists actual duration

Do not force reps on duration exercises.

### 7. Rest timer improvements

- per-exercise rest seconds remains supported
- warmup and work rest may differ
- completing the final set of an exercise should not create an annoying useless rest flow
- quick controls: `+15s`, `-15s`, `Skip`
- timer state should survive short reload/background where technically possible

### 8. Keep-awake during active workout

Use Screen Wake Lock API when supported.

Rules:
- only while an active workout is open
- graceful fallback when unsupported (especially iOS/PWA differences)
- setting toggle in workout preferences
- never block training if permission/API fails

### 9. Free / empty workout

Add `开始自由训练` from home.

Flow:
- create empty WorkoutSession
- add exercises from library
- same logging, rest, notes, history and summary behavior as plan-based workout
- `planId = null` / explicit ad-hoc marker; do not create a fake plan automatically

### 10. History correction

A user must be able to fix a completed workout after noticing a mistake.

Minimum:
- open workout history detail
- edit set weight/reps/RIR/type/duration or assisted-load fields
- delete erroneous set
- recalculate volume, avg RIR, PR presentation and exercise bests

Safety:
- history edit confirmation
- persist atomically as practical
- no silent duplicate session

## P1 — should ship if P0 is stable

### 11. Warm-up calculator

For external-load exercises only.

Input:
- target working weight
- configurable warmup percentages/reps
- rounding increment by equipment type

Default example can be simple and editable, such as:
- 40% × 8
- 60% × 5
- 80% × 3

Output inserts `warmup` sets; it must never overwrite completed work sets.

Do not apply to bodyweight/duration exercises unless explicitly supported.

### 12. Plate calculator

For barbell / plate-loaded compatible exercises.

Inputs:
- target total weight
- bar weight
- available plate inventory

Output:
- plates per side
- impossible target / nearest achievable target when exact load cannot be built

Keep optional and contextual; do not clutter every exercise.

### 13. Superset

Allow linking 2+ exercises into a superset group.

Behavior:
- after completing a set, next-action affordance moves to the next exercise in the group
- rest behavior should not force the normal single-exercise rest flow between paired exercises
- persist group membership in plans and active sessions

Do not build circuits/programming complexity beyond basic supersets.

### 14. Training summary improvements

Add useful, non-social summary:
- duration
- completed work sets
- total volume
- PRs
- avg RIR when recorded
- top exercises
- muscle-group set distribution
- comparison vs previous same routine when data exists

No fake achievements.

### 15. Weekly review

Simple local report using real history only:
- sessions this week
- total work sets
- volume trend
- muscle-group sets
- PR count
- consistency vs weekly target

No AI narrative in V0.3.

## UX rules

- Active workout remains the primary product surface.
- Do not add permanent toolbar clutter for every feature.
- Contextual actions should live behind compact menus or appear only when relevant.
- Main numeric inputs need >=44px touch targets.
- Weight/reps entry should be usable one-handed.
- Preserve dark theme and current visual system unless a change clearly improves logging speed.
- No modal cascade for common logging actions.
- User must always know whether a number is:
  1. Previous
  2. Suggested
  3. Current actual input

---

## Data/model requirements

Review and evolve schema deliberately; increment schema version if persisted structures change.

Likely additions:
- exercise metric type: `reps | duration`
- equipment/load mode metadata
- assisted load fields
- superset group id
- workout source: `plan | free`
- previous-value preference
- wake-lock preference

All migrations must:
- preserve V0.2.1 real history
- preserve active session if compatible
- never call `localStorage.clear()`
- remain idempotent

Export/import must continue to work with the new schema and reject future schemas.
